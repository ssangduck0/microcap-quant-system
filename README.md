# 초소형주 퀀트 시스템 (SQLite + SEC 희석 판별)

## 설치 / 실행
```bash
pip install -r requirements.txt
cp .env.example .env          # SEC_USER_AGENT 에 본인 이름/이메일 입력 (필수)

python scanner.py             # 터미널 1: 스캐너 (계속 실행)
streamlit run dashboard.py    # 터미널 2: 대시보드
python backfill.py --years 10 # 선택: 과거 일봉 채우기 (통계 탭용)
```

## 알아둘 한계
- 희석 상태는 **키워드 검출 결과**입니다. 오탐/미탐이 있으니 대시보드의 SEC 원문 링크로 확인하세요.
- ATM이 검출돼도 **잔여 한도**는 알 수 없습니다. UNKNOWN은 "희석 없음"이 아니라 "확인 못 함"입니다.
- 매수체결 비중은 1분봉 기반 **추정치**이고, 진입/손절/목표는 ATR 기반 **참고 계산값**입니다.
- 토스 랭킹 API는 비공식이라 언제든 바뀔 수 있습니다(실패 시 다른 소스로 대체).
- 지금부터 쌓는 데이터는 하락 랭킹 종목 중심이라 **생존편향**이 있습니다.

## 종목 리포트 탭
대시보드의 `🗂 종목 리포트`에서 종목을 고르고 **리포트 생성/갱신**을 누르면 SEC 공시와 가격 데이터로 만들어 DB에 저장합니다(30초~1분).
- 자동: 회사 개요·역분할·상장유지 경고(8-K Item 3.01), 조달 이력과 공시 전후 주가 반응, 런웨이(SEC XBRL), 내부자 거래(Form 4), 타임라인
- 직접: 워런트·락업 수량, 진입가 사다리, 돌파 가능성 같은 해석은 `내 메모`에 따로 기록
- 리포트는 자동 갱신되지 않으므로 필요할 때 다시 생성하세요.

## 토스증권 Open API (선택)
`.env` 에 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET` 을 넣으면 켜집니다. 없으면 기존처럼 yfinance 만 사용합니다.
1. 토스증권 WTS > 설정 > Open API 에서 키 발급, **허용 IP 관리에 이 PC의 공인 IP 등록** (미등록이면 403)
2. `python toss_check.py` 로 연결 점검 (스캐너를 끈 상태에서)
3. `python scanner.py`

토스를 쓰면: 토스에서 실제 거래 가능한 나스닥 종목만 감시 / 미국 급하락·거래량 랭킹 종목을 우선 분석 / 후보 종목의 1분봉을 토스에서 수집(실패한 종목만 yfinance로 보충) / 환율·미국장 세션을 토스 기준으로 표시.
- 토큰은 클라이언트당 1개만 유효합니다. 토스는 **스캐너만** 호출하고, 대시보드는 스캐너가 DB에 기록한 값을 읽습니다.
- 인증이 실패하면(예: IP가 바뀜) 5분간 토스 호출을 건너뛰고 yfinance 로 계속 동작합니다.
- 체결 내역 API에는 매수/매도 구분이 없어서 '매수체결 비중'은 계속 추정치입니다.
- 계좌·주문 API는 구현하지 않았습니다(읽기 전용).

## 거래량 출처 (volume_check.py 로 확인한 결과)
토스 1분봉 거래량은 yfinance 1분봉 합의 약 59~90%(종목마다 다름)이고, 토스 랭킹 거래량은 하루 누적이 아니라 일정 구간 기준으로 보입니다.
분모(20일 평균 일거래량)가 yfinance 일봉이므로 거래량 배수의 분자도 yfinance 1분봉 합을 씁니다(`VOLUME_SOURCE=yahoo`, 기본).
토스는 가격·봉(낙폭, 매수체결 비중)에만 쓰고, 기준 거래량을 못 구한 종목은 틀린 값 대신 '확인 불가'로 표시합니다.
`.env` 에 `VOLUME_SOURCE=toss` 를 넣으면 토스 분봉 합을 쓰지만 배수가 낮게 나오므로 권하지 않습니다.

## 과거 사례 DB (cases.py)
전일 종가 대비 -10% 이하 급락 '사건'을 일봉 10년치에서 모두 찾아 이후 결과(다음날 시가·고가·저가·종가, 3·5·10일 후, 5일 내 최고·최저)와 함께 저장합니다.
```
python cases.py build --years 10   # 처음 한 번. 수십 분, 중단(Ctrl+C) 후 같은 명령으로 이어하기
python cases.py update             # 매일 한 번(미국 장 마감 후). 새 사건 추가 + 이전 사건 결과 보완 + 신규 상장 종목 추가
python cases.py status             # 진행/오류 현황
```
- 토스 연동이 켜져 있으면 토스의 상장폐지 종목 목록도 함께 시도합니다(가격이 남아 있는 종목만 사건에 들어가며, 못 구한 종목은 대시보드의 '상장폐지 목록 중 가격 확보'로 확인).
- '성공' 기준(다음날 고가 +N%)은 저장하지 않고 대시보드 슬라이더로 바꿔 가며 계산합니다. 일봉이라 고가/저가의 순서와 분 단위 결과는 알 수 없습니다.
- 대시보드 `📚 과거 사례` 탭에서 필터링하고 CSV(엑셀용)로 내려받을 수 있습니다.

## 시가총액 필터
정밀 분석 전에 토스 발행주식수 x 현재가로 시총을 근사해 `MAX_MARKET_CAP_USD`(기본 3억 달러)를 넘는 종목을 제외합니다(`.env` 에서 `MAX_MARKET_CAP_USD=0` 이면 끔).
`manual_tickers.txt` 종목은 항상 유지됩니다. 다중 클래스·ADS 종목은 발행주식수 기준이 달라 시총이 어긋날 수 있습니다.

## 매일 자동 실행 (윈도우 작업 스케줄러)
`run_cases_update.bat` 을 이 폴더(cases.py 와 같은 폴더)에 두고 작업 스케줄러에서 실행합니다. 권장: 화~토 07:30 (한국시간).
미국 정규장 마감이 한국시간 05:00(서머타임 중) / 06:00(11/1 이후)이라 07:30 이면 연중 마감 후입니다.
출력은 `C:\quant_data\cases_update.log` 에 쌓입니다. 이 파일이 UTF-8 설정을 하는 이유: 출력을 파일로 저장하면 윈도우 기본 코드(cp949)로
인코딩되는데 `≈`, `—` 같은 문자가 저장되지 않아 오류가 나기 때문입니다.

## 비슷한 과거 사례 (스냅샷 ↔ 과거 사건)
`📊 퀀트 스냅샷` 표에 `오늘 등락(%)`, `유사 사례 수`, `유사 성공률(%)` 열이 추가됩니다(오늘 등락률이 -10% 이하인 종목만 계산).
종목을 선택하면 상세 화면 아래에 오늘 등락률 ±5%p·거래량 배수 ×/÷2 이내의 과거 급락 사건 수, 성공률(전체 평균 대비), 다음날·5일 후 중앙값, 가장 비슷한 사건 10건이 나옵니다.
허용 범위와 성공 기준(다음날 고가 +N%)은 화면에서 바꿀 수 있습니다. 먼저 `python cases.py build --years 10` 으로 과거 사례 DB가 있어야 합니다.
스캐너를 새 버전으로 다시 시작해야 '오늘 등락률'이 저장되며, 이전에 쌓인 스냅샷은 값이 비어 있어 패널에서 급락률을 직접 조정해야 합니다.

## 종합 점수 (승률 모델)
```
python winmodel.py fit        # 과거 사례로 학습 + 표본 외(최근 24개월) 검증, DB에 저장 (과거 사례 DB가 먼저 필요)
python winmodel.py show       # 저장된 모델의 검증 결과
```
- 전일 대비 -10% 이하 급락 사건의 결과(다음날 고가 +N% / 다음날 종가 +N%)를 가격·거래량 4개 입력(오늘 등락률, 거래량 배수, 전일까지 20일 낙폭, 20일 평균 거래대금)으로 예측합니다.
- 종합 점수 = (희석 상태 가정 배수를 곱한) 예상 확률의 과거 사건 분포 백분위(0~100). 스캐너가 **정규장 마지막 스캔 값**을 스냅샷에 기록합니다(`WIN_MODEL` 로 모델 선택, 기본 high_10).
- 대시보드 `🧪 점수 검증` 탭: 표본 외 AUC·점수 구간별 성과·확률 보정표, 그리고 스캐너가 기록한 점수와 실제 결과를 붙인 **라이브 성과**.
- 희석 상태 배수(`config.DILUTION_MULT`)는 **가정값**입니다. 라이브 성과의 '희석 상태별 실측'이 충분히 쌓이면 실측 비율로 교체하세요.
- 점수 기준 모델 재학습은 데이터가 쌓일 때마다(예: 한 달에 한 번) `python winmodel.py fit` 으로 합니다.

## 종합 점수 v2 (입력 9개 + 2차 모델 자동 선택)
입력: 오늘 등락률, 거래량 배수, 전일까지 20일 낙폭, 20일 평균 거래대금 + **시가 갭, 종가 위치(0=저가·1=고가), 그날 변동폭, 직전 20일 평균 변동폭, 시장 급락 종목 비율**.
과거 사례 DB 에 새 입력이 채워져 있어야 합니다(없으면 자동으로 기본 4개 입력으로 대체):
```
python cases.py build --years 10 --rebuild   # 새 사건 필드(변동폭·종가 위치·직전 변동폭) 채우기. 7~10분
python winmodel.py fit                        # 선형/2차 모델을 학습 구간 안에서 비교·선택, 표본 외 검증
```
스캐너는 새 버전으로 재시작해야 스냅샷에 새 입력(갭·종가 위치·변동폭·시장 비율)이 저장됩니다. 시장 급락 비율은 그날 일봉이 500종목 이상 확보될 때만 계산됩니다.

## 발견 종목 추적 (페이퍼 트레이딩 기록)
스캐너가 저장한 종목(daily_snapshots)이 그 뒤 어떻게 움직였는지 자동으로 채웁니다. 진입가 = 발견한 날 정규장 종가(일봉).
```
python tracker.py update   # 수동 실행 (장 마감 후). `python cases.py update` 끝에도 자동으로 실행되므로 작업 스케줄러에 등록해 두면 매일 자동
python tracker.py status
```
대시보드 `📒 발견 종목 추적` 탭에서 기간·희석 상태·종합 점수·"마감 무렵까지 조건 유지" 등으로 거르고, 성공 기준(다음날 고가 / 5일 내 최고가 / 다음날 종가 + N%)을 바꿔가며
"발견 N개 중 몇 개가 올랐나"(성공률)와 날짜별·누적 추이를 봅니다. 조건 없이 전체 대비 차이도 함께 표시됩니다.

## 로그인하면 스캐너 자동 시작 (윈도우)
`start_scanner.bat` 을 이 폴더에 두고 한 번만 등록합니다. 꺼지면 30초 뒤 다시 시작하고, 출력은 `C:\quant_data\scanner.log` 에 저장됩니다(cmd 창은 뜨지 않음).
```
schtasks /Create /TN "QuantScanner" /SC ONLOGON /F /TR "\"<이 폴더의 전체 경로>\start_scanner.bat\""
```
대시보드도 같은 방식으로 `start_dashboard.bat` 를 `QuantDashboard` 작업으로 등록하면 로그인 시 자동으로 켜지고 `localhost:8501` 로 접속합니다(브라우저는 자동으로 열리지 않음).
**관리자 권한 없이** 하려면 `install_autostart.bat` 을 실행해 시작프로그램 폴더에 두 바로가기(스캐너·대시보드, 최소화 창)를 만듭니다(해제는 `uninstall_autostart.bat`). `schtasks /SC ONLOGON` 은 관리자 권한이 필요합니다(둘 중 한 방식만 사용).
수동으로 띄운 스캐너 창이 있으면 꺼야 합니다(동시에 두 개 실행 금지). 로그가 커지면 가끔 지우세요. 해제: `schtasks /Delete /TN "QuantScanner" /F`
미국 장 시간(한국 17:00~09:00, 정규장 22:30~05:00; 11/1 이후 한 시간씩 늦어짐)에만 켜져 있으면 되고, 낮에 꺼도 손실이 거의 없습니다.

## 노트 (자동 저장)
`📝 노트` 탭: 제목을 정해 노트를 만들고 입력창 밖을 클릭하거나 Ctrl+Enter 를 누르면 **자동으로 DB(quant.db)에 저장**됩니다. 메모장 `.txt` 파일을 여러 개 한 번에 가져올 수 있고(UTF-8/ANSI 자동 판별, 같은 제목은 건너뜀), 전체 백업(.txt) 내려받기가 있습니다.
`🗂 종목 리포트`의 종목별 메모도 같은 방식으로 자동 저장됩니다.

## 목표가 청산 시뮬레이션 (고가 기준 모델)
`🧪 점수 검증` 탭과 `python winmodel.py fit` 출력에 **목표가 청산 평균**이 추가됩니다: 사건일 종가에 사서 다음날 +N% 지정가 매도를 걸고, 못 팔면 다음날 종가에 정리(갭 시작이면 시가 체결 가정)했을 때의 평균 수익·승률·-20% 이하 손실 비율.
손절 없이 목표가만 걸므로 일봉만으로 계산됩니다. 체결 수량·호가 공백·거래정지·수수료는 반영되지 않은 낙관적 수치입니다. 점수가 높은 구간에서 이 지표가 전체보다 좋아야 쓸모가 있습니다.

## 장마감 후보 보드 (🎯 탭)
기존 '장마감 펌핑 체크리스트'를 후보 보드로 바꿨습니다.
- 지금이 정규장이 아니면 **경고**(거래량 배수·종합 점수는 정규장 값 기준이라 프리마켓/데이마켓에서는 의미 없음), 마감 30분 전부터의 값이 기준임을 안내
- **종합 점수** 기준 정렬(점수 없는 종목은 뒤로), 유사 성공률·시가 갭·종가 위치 표시
- 필터: 종합 점수 ≥, 체크리스트 충족 ≥ N/7, 유통주식 ≤, 오늘 등락 -10% 이하만
- 체크리스트는 **항목마다 열을 따로** 두고(낙폭≤-20% · 유통≤2천만 · 거래량≥2배 · 매수≥55% · ATM 없음 · CB 없음 · 희석 확인) ✅/❌ 로 표시, `충족 N/7` 요약. 표 아래 `체크리스트 상세`에서 종목을 고르면 항목별 **현재 값**과 미충족 항목을 보여줌
- 기존 `펌핑점수`는 '참고'로 남김(검증되지 않은 점수)

## 장마감 펌핑 체크리스트 (토스 기준, 🎯 탭)
퀀트 스냅샷과는 **별도 기준**입니다. **대상 = 정규장 마감 1시간 전의 토스 급하락 순위 1~20위**(ETF·ETN·워런트·우선주 제외). 정규장 중 스캐너가 매 사이클 순위를 기록하고(화면에 '현재 순위' 미리보기, 실시간 체결강도 구독 우선), 마감 `CLOSE_WATCH_FREEZE_MIN`(기본 60)분 전이 지난 첫 사이클에 그날 대상으로 **고정**한 뒤 마감까지 그 종목만 기록합니다. 마감 시각은 토스 장 캘린더 기준(조기 폐장 반영, 없으면 동부 16:00). 순위 범위는 `CLOSE_WATCH_TOP_N`(기본 20).

| 항목 | 출처 |
|---|---|
| 과대 낙폭 · 거래량 폭발 · 폭발 후 거래량 감소 · 공급 제한(발행주식수) | 토스 1분봉·일봉·종목정보 |
| 체결강도 상승 | 토스 실시간 웹소켓(체결·호가) — 체결가를 그 순간의 호가와 비교한 매수/매도 체결량 비(추정). 웹소켓이 없으면 1분봉 추정 |
| 매도 호가 얇아짐 · 매도벽 | 토스 호가(웹소켓 분 단위 시계열, 없으면 REST 샘플). 호가 단계 수는 `toss_check.py` 11번으로 확인 |
| 장중 희석 · 워런트 · 자금조달 유형/출회 제한 | SEC 공시 키워드(원문 확인 필요) |
| 하킷(하한)·상킷(상한) | 업킷 UpCuit API(https://upcuit.com/api/v1/halts, 무료·무인증), 실패 시 나스닥 공식 RSS. 방향은 LULD 밴드 가격 vs 정지 직전 토스 1분봉 가격 |
| 공매도 거래량·대차 수수료·잔고 | Fintel API(.env 의 `FINTEL_API_KEY`) — 참고 항목, 등급 미반영 |

- 등급: BEST(패턴 5/6 이상 + 장중 희석 없음 확인 + 출회 제한 조달 또는 공급 제한) · 후보 · 관찰 · 희석 위험 · 낙폭 미달. 기준값은 화면에서 조정(저장된 원본 수치를 다시 판정)
- 필요한 설정: `pip install websockets`(실시간 체결강도), `.env` 에 `FINTEL_API_KEY=...`(공매도, 선택). 꺼짐 옵션: `TOSS_WS_ENABLED=0`, `HALTS_ENABLED=0`
- 가정 확인 점검: `python toss_check.py` 11~14번(호가 단계 수, 일봉 '오늘 봉' 찾기, 일봉 거래량 vs 1분봉 합계, 웹소켓 연결), `python fintel_check.py 티커`(Fintel 원본 응답), `python halts_check.py`(거래정지: 업킷/나스닥, `--nasdaq` 로 RSS만)
- 토스 웹소켓은 계정당 동시 연결 2개까지, 연결당 구독 100건(체결+호가 = 종목당 2건 → 최대 50종목)입니다. 다른 곳에서 같은 계정으로 웹소켓을 쓰면 연결이 밀려날 수 있습니다.

## 🧪 가상매매 · 📈 차트 분석 · 📰 뉴스 모음 · 🏁 순위 가중치
- 가상매매(추적): 매일 아침 종합 순위 1~3위를 직전 종가로 $1,000씩 → 익절 +20% · 손절 −10%(같은 날 둘 다면 손절) · 최대 3거래일 종가. 같은 종목 중복·같은 날 재매수 없음
  이번 장부 수익률·승률·평균·열린 포지션·누적 손익·거래 기록, '초기화'로 새 장부(지난 장부 결과 표), 신호별 성과(있을 때 vs 없을 때 평균) → 가중치 조정 참고
  규칙: 관리 모드 '가상매매'(개수·익절·손절·보유일·금액)
- 순위 가중치: 관리 모드 '순위 가중치' — 종합 = 강도 × RANK_W_STRENGTH + 임박도 × (1 − 그 값), 강도 항목 비중(매집·압박·스퀴즈·멀티·공시·내부자, 합이 1 아니어도 비율로)
- 차트 분석(발굴): 순위 1~5위 + 다른 티커 탭, 가격·이동평균 3개·일목 구름 / RSI(바닥 기준선) / MACD(히스토그램) 차트,
  신호: RSI 바닥 반등·과매도·과매수, MACD 골든(+RSI 저점)·데드크로스(최근 N일), 이평선 정배열·역배열, 일목 구름 위·안·아래 + 구름 두께 %(얇음 기준 설정). 설정 저장(주인)
- 뉴스 모음(오늘): GlobeNewswire 공식 Atom/RSS(10분) → '(Nasdaq: ABCD)' 표기로 종목, 호재(FDA·계약·제휴·실적·특허·피인수·상향 상장)·악재(공모·사모·병합·상장유지·존속·워런트) 키워드
