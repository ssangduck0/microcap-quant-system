# 토스증권 Open API 주문 기능 사전 조사 (2026-10-28 밤)

4단계 '소액 자동매매'를 할 수 있는지, 하려면 무엇이 필요한지 **문서만 읽고** 정리한 것(코드 변경 없음).
출처: 공식 개요 `openapi.tossinvest.com/openapi-docs/overview.md` · 공식 FAQ `…/faq.md` · 공식 모델 문서(`OrderCreateQuantityBased.md` 등) · 제3자 가이드(algolab, 2026-08-04 작성·10-14 재확인). 공식 인터랙티브 문서(`developers.tossinvest.com/docs`)는 자바스크립트로만 그려져 읽지 못했고, 같은 내용의 마크다운 원본을 읽음.

## 결론 한 줄
**가능하다.** 개인 계좌로 발급한 키로 미국 주식 지정가·시장가 주문, 정정·취소, 조건주문(OCO·OTO)까지 된다. 모의투자(샌드박스)는 **없다**. 우리 서버 IP 는 이미 허용 목록에 있다(시세를 받고 있으므로). 제약은 세 가지: ① 클라이언트당 **토큰 1개**(스캐너와 주문이 토큰을 같이 써야 함) ② 주문에 **세션 지정 필드가 없음**(시간외 지정가가 어떻게 처리되는지는 소액 실주문으로 확인해야 함) ③ 짧은 시간 대량 주문은 **어뷰징으로 매매 제한**.

## 사실 표

| 항목 | 내용 |
|---|---|
| 발급 | 토스증권 계좌 → WTS(PC 웹) 설정 → Open API 에서 `client_id`·`client_secret`. 공동인증서 불필요. 허용 IP 미등록이면 403 |
| 인증 | `POST /oauth2/token`(client_credentials), 유효 24시간(제3자 가이드). **클라이언트당 토큰 1개 — 새로 받으면 이전 토큰 즉시 무효**. 계좌·주문 호출엔 `X-Tossinvest-Account: {accountSeq}` 헤더 필요(`GET /api/v1/accounts`) |
| 주문 생성 | `POST /api/v1/orders` — `symbol`(미국은 티커), `side`, `orderType`(LIMIT/MARKET), `price`(LIMIT 필수, $1 미만은 소수 4자리), `quantity` 또는 `orderAmount`(달러 금액, 미국 시장가 전용·정규장만), `timeInForce`(DAY 기본 · CLS=미국 LOC · OPG=국내), `clientOrderId`(멱등키 10분), `confirmHighValueOrder`(1억 원 이상) |
| 세션 | **주문 필드에 세션 구분 없음.** 시장 캘린더(`/market-calendar/US`)가 데이마켓·프리·정규·애프터 시간을 줌. 조건주문 문서: "해외 주식은 거래 가능한 모든 시간대에 발동". 국내는 시간 외 `422 order-hours-closed`. → 미국 시간외 지정가(DAY)가 그 세션에서 체결 대기하는지, 정규장 마감에 취소되는지는 **실주문으로 확인 필요** |
| 소수점 | 소수점 수량은 미국 **시장가 매도**만(6자리), 소수점 매수는 `orderAmount`. 둘 다 정규장 시작~종료 1시간 전만 |
| 정정·취소 | `POST /orders/{id}/modify`(미국은 가격만) · `POST /orders/{id}/cancel`(체결분 불가) |
| 조회 | `GET /orders`, `/orders/{id}`, `/buying-power`, `/sellable-quantity`, `/commissions`(수수료율 소수, 예 0.00015), `/holdings`, `/accounts` |
| 조건주문 | `POST /api/v1/conditional-orders` — SINGLE(조건 1개, 개수 제한 없음) · OCO(매도 2개, 하나 체결 시 나머지 취소) · OTO(매수 뒤 매도 감시). OCO·OTO 는 **지정가만**, 종목당 1개. 이미 조건을 만족한 가격이면 거부. 수정은 취소 후 새 ID. 상태 WATCHING·PAUSED·ORDERING·ORDERED·COMPLETED·EXPIRED |
| 호출 한도(초당) | ORDER 10 · ORDER_INFO 6(09:00~09:10 KST 3) · ORDER_HISTORY 5 · CONDITIONAL_ORDER 5 · ACCOUNT 1 · ASSET 5 · MARKET_DATA 15 · MARKET_DATA_CHART 20. 429 는 `Retry-After` 뒤 지수 백오프. 의심 IP 는 초당 1회로 제한될 수 있음 |
| 어뷰징 | "주문을 짧은 시간에 대량 반복하면 어뷰징으로 일정 시간 매매 제한, 반복 시 연장"(FAQ) |
| 실시간 | WebSocket `wss://openapi-ws.tossinvest.com/ws/v1`(계정당 연결 2개·연결당 구독 100건·180초 무수신 종료). 체결·호가는 유실 가능, 개인 주문 이벤트는 세션 안에서만 보장 → 재연결 뒤 `GET /orders` 로 재동기화. 우리는 이미 tossws 로 쓰는 중(연결 2개 한도 주의) |
| 모의투자 | **없음.** 서버는 `openapi.tossinvest.com` 하나. 첫 주문부터 실계좌 |
| 금지·정책 | 자동매매를 금지하는 문구는 없음. **"API 정보는 투자자 본인의 매매 목적에만 이용, 상업적 이용 제외, 제3자 배포 엄격 금지"**(FAQ) |
| 기타 | 달러 부족 시 자동환전 없음(미리 환전). 레버리지·인버스 ETF 는 앱에서 사전 요건 필요. 주문 최대 30억 원 |

## 우리 4단계에 주는 뜻

| 주제 | 판단 |
|---|---|
| 어디서 주문하나 | **스캐너 프로세스 안**(토큰 1개). 별도 프로세스가 토큰을 받으면 스캐너 시세가 끊김. 대안: `toss.TossClient` 가 토큰을 DB(meta)에 저장해 공유 — 작은 변경이지만 두 프로세스가 동시에 갱신하면 또 충돌하므로 스캐너 안이 안전 |
| 구조 | `broker.py`: `TossClient` 에 주문 4개(생성·취소·조회·매수가능금액)와 조건주문 2개 추가 + 안전장치(기본 **dry-run**, 하루 주문 수·종목당 금액·총 노출 상한, `clientOrderId` 멱등, 429 백오프, 주문 전 `buying-power` 확인, 모든 응답의 `code`·`requestId` 기록) |
| 전략별 적용 | 🐷 저금통 저점 매수·🏁 순위(직전 종가 매수): 정규장 지정가 → 바로 가능. 🌙 애프터 스캘핑·🎯 장마감: **시간외 지정가 동작 확인 뒤**. 익절·손절: 미국은 모든 세션에서 발동하는 **OCO 지정가 2개**(시장가 손절이 필요하면 SINGLE MARKET 따로) |
| 첫 단계 | ① 정규장에 1주 왕복(매수→매도) ② 애프터에 1주 지정가 왕복(세션 동작 확인) ③ 한 전략(저금통)만 종목당 $100 · 하루 3건 · 2주 ④ 가상매매 장부와 실제 체결을 나란히 비교 |
| 전제(사용자 결정) | 실계좌 위험 감수 범위(총액·하루 한도), 어느 전략부터, 환전해 둘 달러 금액 |
| ⚠️ 정책 검토 | FAQ 의 "제3자 배포 금지"가 **방문객 사이트(guest.sduckquant.com)** 에 토스 시세·랭킹에서 나온 숫자를 보여 주는 것에 해당할 수 있음. 자동매매와 별개로 **사용자 판단 필요**(방문객 화면에서 토스 기반 값을 빼거나, 가공된 판정만 보여 주기) |

## 다음에 할 일(승인 뒤)
1. `broker.py` 설계안(안전장치 수치 포함)을 먼저 보여 주고 승인 → 구현(테스트는 가짜 클라이언트) → 배포.
2. 사용자가 WTS 에서 주문 권한·환전 확인 → 1주 왕복 테스트는 사용자 PC 가 아니라 **서버에서**(허용 IP).
3. 2주 소액 운영 결과를 🏆 성과 공표에 '실매매' 로 기록(📒 매매 일지 표 재사용).
