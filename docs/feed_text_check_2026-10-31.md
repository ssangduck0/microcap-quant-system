# 공시 판정 본문 검증 (2026-10-31 · 분석만 · 결론 '그대로')

## 왜
`secfeed.enrich` 는 공시 목록 페이지의 첫 `/Archives/…` 링크를 판정용 본문으로 읽는다. iXBRL 공시(요즘 8-K 대부분)는 주 문서가 `/ix?doc=` 링크라
실제로는 **첫 첨부(보도자료·계약서) 76% · 전체 묶음 .txt 23% · 주 문서 0.3%** 를 읽는다(아래 표본 900건). 주 문서로 바꾸면 판정이 크게 바뀌므로(51%)
어느 쪽이 주가 반응을 더 잘 맞히는지 먼저 쟀다. (핵심 문장·병합 일정은 판정과 무관해서 커밋 ad05aaa 에서 이미 주 문서로 바꿈.)

## 방법
- 표본: 🔬 이벤트 연구(`ev_docs`·`ev_labels`)에서 지난 1년 8-K 900건 무작위(seed 11). 정답 = 시장(IWM) 대비 초과 반응 `abn0`(발표 반응일) · `abn5`(5일).
- 같은 공시를 네 가지로 `secfeed.classify` 판정:
  - **항목만**(본문 없음) · **A 지금**(첫 `/Archives` 링크) · **B 주 문서만** · **C 주 문서 + EX-99 + A 문서**
- 지표: 점수와 반응의 순위상관(오차 ≈ ±1/√n = ±0.033) · 호재/악재 묶음 중앙값 차이 · 방향 적중(점수 ≠ 0).
- 서버 읽기 전용 · SEC 원문 약 3,600번 · 612초. 원자료 서버 `/tmp/qs_split/textval.csv`.

## 결론
- **지금 본문(A)이 가장 낫거나 같다** → 판정 본문은 바꾸지 않음. 주 문서(B)는 실적 8-K 가 '첨부 참고' 껍데기라 호재를 거의 못 잡아 발표일 반응을 덜 맞힘(+0.052).
- C(다 합치기)는 A 와 판정이 6%만 다르고 성적도 같음 → 요청 수만 늘어 이득 없음.
- 본문은 확실히 도움이 됨(항목만 +0.017 → A +0.116).
- 참고(만들지 않음): B 는 악재를 더 많이 잡고 소형주에서 방향 적중이 높음(악재 92건 · 5일 중앙 −5.9%, 방향 67%) — 'A 판정 + 주 문서에서만 나온 악재 태그' 같은 혼합은 표본이 작아(호재 11건) 지금은 근거 부족. 공시가 더 쌓이면 다시 볼 수 있음.
- 같은 링크 고르기가 `fundscan.py:237` 에도 있으나, 위 결과상 첫 첨부(계약서·보도자료)를 읽는 게 손해가 아니라 그대로 둠.
