## 0. 한 줄
🧪 가상매매(`papertrade`)가 이미 내리는 "언제 사고 판다" 결정을 그대로 받아, **안전장치를 통과한 것만** 토스 실주문(지정가)으로 내고, 체결을 📒 매매 일지와 새 표에 기록한다. 기본은 **꺼짐(dry-run)**. 1단계는 🐷 저금통 한 전략, **1주 모드**(종목당 1주), 하루 3건, 3~4주.

## 1. 원칙 6가지

| 원칙 | 왜 |
|---|---|
| 결정과 실행 분리 | 전략 규칙은 가상매매 그대로. broker 는 "낼지 · 얼마나 · 어떤 가격" 만 정함 → 가상 장부와 실제 장부를 1:1 로 비교할 수 있음 |
| 지정가만(시장가 금지) | 동전주는 호가 틈이 커서 시장가면 몇 % 가 날아감. 매수 = 기준가 × (1 + 1%), 매도 = × (1 − 1%). 시간외는 어차피 지정가만 됨 |
| 기본 dry-run | `LIVE_TRADING=0` 이면 주문 본문까지 만들고 기록·알림만. 켜려면 관리 모드에서 두 단계(스위치 + "실계좌 주문을 켭니다" 확인 문구) |
| 주문은 스캐너 안에서만 | 토큰이 클라이언트당 1개라 다른 프로세스가 토큰을 받으면 스캐너 시세가 끊김. 대시보드의 "지금 팔기" 버튼은 **요청 표**에 넣고 스캐너가 다음 주기(≤1분)에 처리 |
| 멱등·기록 | `clientOrderId = 전략-티커-날짜-방향-n`(36자 이내, 10분 멱등). 모든 요청·응답의 `code`·`requestId` 를 표에 남김 |
| 킬 스위치 | 하루 실현손실 한도 초과 · 연속 거부 3회 · 토스 403/계좌 제한 → 미체결 전부 취소 + `LIVE_TRADING=0` 저장 + 텔레그램 |

## 2. 안전장치 수치(관리 모드에서 조정, 괄호는 허용 범위)

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `LIVE_TRADING` | 꺼짐 | 실주문 스위치(두 단계 확인) |
| `LIVE_STRATEGIES` | `piggy` | 실주문을 내는 전략 목록(1단계는 저금통만) |
| `LIVE_ONE_SHARE` | **켜짐** | 1주 모드: 금액과 상관없이 종목당 1주만(11월 말 결정 뒤 끄면 아래 금액 적용) |
| `LIVE_USD_PER_TRADE` | $100 (10~500) | 1주 모드가 꺼졌을 때 종목당 매수 금액. 수량 = 내림(금액 ÷ 지정가), 1주 미만이면 안 삼 |
| `LIVE_MAX_ORDERS_PER_DAY` | 3 (1~10) | 하루 매수 주문 수(매도·취소는 별도, 어뷰징 방지로 정정은 안 함) |
| `LIVE_MAX_OPEN` | 3 (1~10) | 동시에 들고 있을 종목 수 |
| `LIVE_MAX_EXPOSURE_USD` | $500 (50~5,000) | 보유 평가액 + 미체결 매수 합계 상한 |
| `LIVE_MAX_PRICE` | $5 (0.5~50) | 이 가격 넘는 종목은 안 삼(동전주 범위 유지) |
| `LIVE_MIN_DOLLAR_VOL` | $50,000 | 20일 평균 거래대금 미만이면 안 삼(체결·탈출 가능성) |
| `LIVE_LIMIT_SLIP_PCT` | 1.0% (0.2~3) | 지정가 여유폭 |
| `LIVE_ORDER_TTL_MIN` | 30분 (5~240) | 미체결 지정가 취소까지. 그날 다시 안 삼 |
| `LIVE_DAILY_LOSS_USD` | −$50 | 그날 실현손실이 넘으면 킬 스위치 |
| 금지 목록(고정) | — | 희석 ATM·ELOC·CB, ⑥ ❌(+20% 초과), 상장유지 미달 통지(기한 60일 이내), 🚫 거래 불가(상폐·ETF), 레버리지 ETF, 당일 이미 거부된 종목 |

## 3. 구성(새 파일 2개 + 기존 파일 보강)

| 곳 | 내용 |
|---|---|
| `toss.py`(기존) | 주문 메서드 7개: `accounts()` · `buying_power(symbol)` · `order_create(symbol, side, qty, limit_px, client_order_id)` · `order_cancel(id)` · `orders(status, since)` · `order(id)` · `cond_create(oco…)`/`cond_cancel`. 새 그룹 버킷 ORDER 10/s · ORDER_INFO 6/s · ACCOUNT 1/s · CONDITIONAL_ORDER 5/s. 헤더 `X-Tossinvest-Account`. 오류 코드 → `TossError(code)`(insufficient-buying-power · order-hours-closed · ip-not-allowed · account-restricted · idempotency-key-conflict) |
| `broker.py`(새) | `can_buy(conn, strategy, t, px, qty) -> (ok, 이유)` 모든 한도·금지 목록·매수가능금액·중복 미체결 확인 → `place_buy/place_sell` → `sync()`(주기마다 `GET /orders` 1회: 체결·취소 반영, TTL 지난 미체결 취소, 체결되면 📒 `trade_journal` 자동 기입 signal=전략) → `arm_exit()`(체결 즉시 OCO 익절·손절 지정가 등록, 미국은 모든 세션 발동 · 거부되면 SINGLE 손절만) → `kill(reason)` |
| `broker_ui.py`(새, ⚙️ 관리 모드 '💵 실매매') | 스위치(두 단계) · 한도 입력 · 오늘 주문/보유/노출/손익 · 미체결 표(취소 버튼 = 요청 표) · 킬 스위치 · 최근 거부 이유 |
| DB(새 표만) | `live_orders(client_order_id PK, strategy, ticker, side, qty, limit_px, status, order_id, filled_qty, avg_px, code, request_id, created_at, updated_at, note)` · `live_requests(id, kind, ticker, created_at, done_at)`. 기존 표 변경 없음 |
| 연결 지점 | `papertrade.open_trade` 가 True 를 돌려주는 순간 `broker.mirror(strategy, t, px, tp_px, sl_px)`(전략이 `LIVE_STRATEGIES` 에 있을 때만) · `papertrade.update/live_check` 가 청산을 판정하면 `broker.sell(t, 이유)` · `scanner.run_cycle` 끝에 `broker.sync(tc)` · `cases.update` 아침에 `broker.daily_report()`(텔레그램 한 줄) |
| 알림 | 접수·체결·거부·TTL 취소·킬 스위치 → 텔레그램(`notify.send_telegram`) |

## 4. 전략별 적용 순서

| 단계 | 전략 | 주문 | 청산 | 조건 |
|---|---|---|---|---|
| 1 (2주) | 🐷 저금통 🟢 저점 구간 | 정규장 지정가(신호가 +1%) | OCO: 익절 = 박스 상단 · 손절 = 박스 하단 −5% (가상매매와 같음) | 1주 왕복 테스트 통과 |
| 2 | 🏁 종합 순위 · 🎯 PICK 유력 | 정규장 개장 뒤 지정가(직전 종가 +1%) | OCO +20%/−10% · +30%/−15% | 1단계 2주 비교에서 체결가 차이 ≤ 2% |
| 3 | 🌙 애프터 스캘핑 · 🎯 장마감 | 시간외 지정가 | 당일 매도 마감 전 지정가, 안 팔리면 다음 정규장 시장가 아님·지정가 반복 | **시간외 지정가 동작 1주 테스트**로 확인 뒤 |

## 5. 테스트(인터넷 없이)
가짜 TossClient(접수 → 다음 `sync` 에 체결 · 거부 코드 주입 · 429 · 토큰 만료) 로: 한도 경계 전부(금액·건수·노출·가격·거래대금·금지 목록) · dry-run 이 실제 호출을 0번 하는지 · 멱등 재전송 · TTL 취소 · OCO 폴백 · 킬 스위치 · 요청 표 처리 · 📒 자동 기입 · 오프라인 모드에서 실 API 차단. 관리 화면 AppTest.

## 6. 실계좌 절차(사용자가 할 일)
1. WTS → Open API: 키 권한에 **주문** 포함 확인, 허용 IP 에 서버(이미 있음) 확인.
2. 달러 환전. 1주 모드는 **$50** 이면 충분(동전주 1주 $0.5~5 × 3종목 + 여유). 자동환전 없음.
3. `broker.py probe` 1주 왕복(정규장, 저가 대형주 1주 → 체결 → 매도) — 서버에서, 사용자 참관(텔레그램으로 단계별 알림).
4. 애프터 1주 지정가 테스트(저가주 1종목) → 세션 동작 기록.
5. 관리 모드에서 `LIVE_TRADING` 켜기(두 단계) → 저금통 2주.

## 7. 위험과 한계(솔직하게)
- 동전주 지정가는 **미체결이 많다**. TTL 뒤 취소하고 그날은 재시도 안 함(어뷰징 방지) → 가상매매보다 체결 수가 적다.
- 가상 체결가(신호 순간 가격·직전 종가)와 실제 체결가의 차이가 전략 성적을 바꿀 수 있다 → 📒 에서 전략별로 비교해 2단계 진입 기준(≤ 2%)으로 삼는다.
- 토스 장애·403·계좌 제한 때 보유 종목의 손절 주문이 안 나갈 수 있다 → OCO 는 **서버 쪽에 등록**되므로 우리 스캐너가 죽어도 작동(이 점이 OCO 를 쓰는 이유).
- 돈: 1단계 최대 노출 $300(3종목 × $100), 일손실 킬 −$50.
- 정책: 방문객 사이트의 토스 데이터 노출은 별개 결정(`HANDOFF` 5절).
